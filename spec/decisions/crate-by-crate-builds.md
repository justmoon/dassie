# CI builds the Rust workspace crate by crate

**Areas:** [Engineering](../engineering.md#ci-rebuilds-only-what-changed), [Testing](../areas/testing.md#levels)

## Facts

- The flake's checks run on a shared Nix builder, which keeps every derivation it built by its inputs. A check whose inputs did not change costs nothing; one whose inputs changed runs in full, however little changed.
- With crane, the workspace's tests and clippy were each one derivation over every crate's source. Only the dependencies were kept apart (`buildDepsOnly`), so an edit to any line compiled all twenty crates again, twice, and ran every test, about two minutes of compiling before a test ran, on every push.
- Most pull requests touch one or two crates, and most crates sit below few others: an edit to `dassie-node` concerns only what is built on it.
- crate2nix describes the workspace as one buildRustCrate derivation per crate, from Cargo's own resolution (`Cargo.lock`, features, targets). Vorstand's own repository builds this way.

## Decision

- **Each crate builds in a derivation of its own,** from its own directory and the files outside it that it reads (`nix/rust/default.nix`), so an edit compiles the crate edited and those built on it, and nothing else. `nix/rust/Cargo.nix` is crate2nix's output, committed, and a check (`cargo-nix-current`) fails while it differs from what `nix run .#cargo-nix` makes of the manifests and the lockfile.
- **Each crate has its own checks:** its tests (`crate-<name>-test`), clippy over its library and binaries, and clippy over its tests and examples. A change runs the tests of the crates it reached, and every other check is kept.
- **A crate's tests build target by target:** its unit tests, and each file in `tests/` and each example in a derivation of its own, from the library built with the features its tests turn on. An edit to one test file compiles that file; the crate's library source leaves out `tests/` and `examples/`, so editing them rebuilds no crate above.
- **The tests still run under nextest,** each in its own process, from the binaries built ([Testing](../areas/testing.md#levels)), with the ci profile's checks: overflow checks and debug assertions on, the dependencies optimized. The workspace's crates compile at opt-level 1 in sixteen codegen units, as fast to build and no slower to test; paths are remapped to Cargo's, so a panic names `crates/<name>/src/...` as a local `cargo test` does.
- **The desktop app is checked with Cargo,** apart: Tauri's build scripts pass their dependents metadata under names buildRustCrate cannot pass on.

## Accepted

- **A crate that reads a file outside its directory names it** in `nix/rust/default.nix`; until it does, its build fails for want of the file.
- **`nix/rust/Cargo.nix` is regenerated by hand** after a change to a manifest, the lockfile or a crate's targets, and a pull request that forgets fails a check.
- **CI no longer builds exactly as `cargo test` does:** the same code and checks, in other optimization settings. A test that passes only at one optimization level is a bug in the test.
- **No doc tests:** buildRustCrate does not run them. A doc example that is a test moves into the crate's tests.

## Rejected

- *crane with finer source filters:* one Cargo build over the workspace still compiles every member whose source is in it, and splitting it per crate means one dependency build per crate, the same dependencies compiled again for each.
- *Cargo's incremental cache, kept between CI runs:* it is not keyed by input, so a run trusts whatever the last one left, and two runs cannot share it.
- *Tests in one derivation per crate, as buildRustCrate builds them:* it compiles the library, its unit tests and every test file one after another on one core; `dassie-node`'s took eight minutes.
