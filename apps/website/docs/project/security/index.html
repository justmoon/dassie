Report a security issue

If you found a way to attack a Dassie node, its wallet, its peers or its releases, thank you. Please tell us privately first, so that it can be fixed before anyone else learns of it.

Early days. Dassie takes test money only: a node refuses the live realm. A flaw that would cost real money later matters just as much now, while it is cheap to fix. How far along it is

How to report it

Tell a maintainer privately, and talk it through with them there.

  1. Join Dassie's Discord.
  2. In a public channel, say that you have a security issue to report and ask a maintainer to message you. Leave every detail of the issue out of that message.
  3. Once a maintainer has written to you directly, describe what you found there, as below.

Careful. Please don't open a public issue, post the details in a Discord channel or send a pull request for a security issue. Each of those is public the moment you send it.

What to include

  • the version you found it in (dassie --version), or the commit, if you read the code;
  • the part it is in: the node, the wallet, the desktop app, the dassie command, a settlement hub, the installer and updater, the release mirror, or dassie.land;
  • the steps to reproduce it, or a proof of concept, as small as you can make it;
  • what an attacker gains, and what they need first: a peer, a node of their own, the owner's login, a place on the network path;
  • whether you have seen it used against anyone;
  • how you would like to be credited, if at all.

Testing safely

Try your attack on nodes you run yourself. The local dev network starts several nodes on your machine, with a fake XRP Ledger, in one command. Please don't test against other people's nodes, the testnet's bootstrap nodes or the release mirror: others rely on them.

What happens next

  1. The maintainers read your report and answer you. Dassie is a small project, so this can take a few days.
  2. Together you work out how serious it is, and the fix is prepared in private.
  3. The fix ships in a signed release. Nodes installed with the installer look for a new release once a day and switch to it by themselves. On NixOS, and in the desktop app, which does not update itself yet, the owner takes it by building the new version. Updates and rollback says more.
  4. Once nodes have had time to update, the maintainers can publish an advisory on GitHub, crediting you if you want that.

Please keep the issue to yourself until the fix is out. If you plan to write about it, say so in the report, and agree on a date.
