Network and peers

The Network page shows your node among its neighbors: who it knows, who it peers with, and how it stands with the network. This page walks you through it, and through ending a peering or banning a node when you need to.

Early days. Dassie takes test money only: a node refuses the live realm. How far along it is

The page at a glance

Open Network in the top menu. At the top right of every page, next to the menu, a dot and a count such as 12 nodes tell you how many nodes your node knows, and whether the wallet is connected to it, still connecting, reconnecting, or failed. Select it to open the Nodes debug page.

The Network page has three parts:

  • The graph. Your node and every node a route reaches, with a line where both ends list each other. A peer that is offline, or that does not list your node back, has no line. Each node keeps its place as the network changes. Select a node to see its details.
  • Nodes. Every node your node knows, grouped by how far it is: This Node, Direct Peers, Peers Not Routed and Offline Peers, Other Nodes two or more hops away, and No Connection for nodes no route reaches. Each shows its name, or the start of its ID, and its URL.
  • Details. Your own node's standing, or, once you select another node, that node's details.

Registered or not

A node with a public address and a domain name is a core node. It joins the network by registering with the bootstrap nodes. Each keeps a list, and a node that more than half of them list is a member, which every other node then knows about.

On a core node, the details card is Details for Your Node, with a section called Tier 1 Registration:

  • Registered or Not registered: whether enough bootstrap nodes list your node.
  • Listed by 3 of 4 bootstrap nodes: how many list it.

A new node has no bootstrap nodes yet: the default list is empty until the testnet's bootstrap nodes get their new node IDs. So out of the box your node runs alone. Its card says Not registered and Listed by 0 of 0 bootstrap nodes, and it finds no peers, until you set DASSIE_BOOTSTRAP_NODES to the testnet's nodes; see Environment variables and Configure your node.

With bootstrap nodes set, your node registers by itself when it starts, and renews before a registration lapses. It shows Not registered for a while at first: each bootstrap node first checks that your node's URL answers, and your node then has to fetch their lists to see itself on them.

To see each bootstrap node, select Register (or Update registration). The page lists each one with whether it lists your node, when your node last registered, and when it last fetched that node's list. Renew now registers again at once.

The rate feed

Below the registration, a core node's card shows its Rate Feed: the rates your node converts at, which it publishes over UDP for market makers to read.

Badge Means
served It publishes, at the address shown, to that many subscribers. The lines below count what it sent and took.
sends failed It publishes, but some sends failed or ran out of time.
not served It starts once your node has a domain name.
none The node has no UDP socket for it, so it publishes nothing.

The feed needs UDP port 7768 open; see Requirements. To read a feed yourself, see Read a rate feed.

Uplinks and relay

A node without a public address, such as the desktop app or a server behind a router, is a periphery node. It registers with no bootstrap node. Its card says Periphery Node and shows two things instead:

  • Uplinks. The core nodes it peers with, which carry its payments in and out, each connected or not connected, with when it was last heard from. With none yet, no payment reaches your node: it looks for core nodes that share a settlement hub with it. In the graph, your node has a line to each uplink it reaches directly.
  • Relay. The node that Open Payments apps reach yours through, with connected, connecting or unreachable. There is no default relay yet, so it says None until you set DASSIE_RELAY, and until then apps cannot reach your node.

For setting a relay or pinning uplinks on a server, see A server without a public IP. For how it fits together, see Core and periphery.

Peers and how they settle

Once it knows bootstrap nodes, your node finds its peers by itself: nodes that share a settlement hub with it. Select any node, in the graph or the list, to see its details:

Distance

How many hops away it is, or no route.

Settles with

The settlement schemes that node says it runs, by their IDs, such as hub-xrpl-testnet-xrp.

Neighbors

The nodes it lists as its own peers.

Peering

none, requesting, peered or terminating: how your node stands with it.

For a peer, the details go on:

Settles on

Each hub the two of you settle over, in the order you agreed, with what your node owes the peer there, net. A negative amount means the peer owes yours. A method may carry a badge:

  • Winding down: your node takes no new payments on it, asks the peer to settle once, then stops settling there. This happens, for example, while you remove that ledger.
  • Short of room: the peer has not settled for a while, so no payments go through it there until it does.
Status and Last heard

Whether the peer is online now, and when it last spoke.

Advertised

Whether your node tells the network it can route through this peer. A peer that is unhealthy for a while is taken out of that, and comes back once it is healthy again; it stays peered all the while.

Ending, because

Shown while a peering ends, with the reason.

For what peers, credit and holds mean, see Peers and holds.

End a peering

Your node ends peerings with peers that stay silent or short of room for long by itself. You rarely need to. If you do:

  1. Select the peer, and then Terminate peering.
  2. Confirm with Terminate.

Your node first asks the peer to settle once more, without saying why, and takes no new payments from it. Then it tells the peer, and once the payments in flight are done, the peering ends. What either side still owes stays on the books, to be settled if you peer again. The two do not peer again for a day, unless your node restarts.

Ban a node

A ban is for a node you never want to deal with. Select the node, then Ban node, and confirm with Ban.

Your node ends any peering with it at once: it stops routing through it and tells it now, without asking it to settle first. What it owes stays on the books. The details then say Banned by you. Your node never peers with it again until you select Unban node. A ban lasts across restarts.
