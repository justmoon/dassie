Release notes

What each release brings, newest first. A node installed with the installer's systemd units looks for a new release once a day; on NixOS, your flake decides.

dassie --version and dassie status name the version you run. How a node moves to a new release, and back, is in Updates and rollback; where releases come from, and how each is signed, in Release mirror and key. The same notes are on the architecture page.

0.3.0 starts the testnet afresh: a node from 0.2.x peers with no 0.3.0 node, and its phrase and database don't work with 0.3.0. Its daily update installs 0.3.0, which refuses the old database and doesn't start, so the update goes back to 0.2 and dassie status says so. Move the node's data aside, install the newest release, and set the node up again with a new phrase, from a fresh database: A node from the 0.2 releases has the steps.
