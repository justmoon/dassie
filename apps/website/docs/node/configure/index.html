Configure your node

Most of your node's settings live in its database, and you change them in the wallet. A few belong to the server it runs on. Those are environment variables, and you set them with a systemd drop-in.

Where settings live

What Where you change it
The domain name and its certificate sudo dassie init, see Certificates
Ledgers, hubs, peers, names, exchange rates, apps The wallet, see Use your wallet
How much the node logs, its relay, its uplinks, extra certificate authorities Environment variables, on this page
Validating a settlement hub A file the environment names, see Validate a settlement hub

The node reads its environment once, when it starts, and checks every variable before it starts anything. A value it cannot use stops it with a message that names the variable.

systemd drop-ins

The installer puts the node's unit, dassie.service, in /etc/systemd/system/, and each update may replace it. Your own settings go in a drop-in beside it, which updates leave alone.

  1. Open the drop-in in your editor:

    $sudo systemctl edit dassie

  2. Add a [Service] section with your variables, one Environment= line each, and save:

  3. Restart the node, so that it reads them:

    $sudo systemctl restart dassie

  4. Check that it came up:

    $dassie status

    If it says Dassie is not running., the log says which variable it refused: journalctl -u dassie -n 20.

systemctl cat dassie shows the unit with every drop-in, so you can see what is set.

A value that holds double quotes, such as the JSON of a relay, goes in single quotes around the whole assignment: Environment='DASSIE_RELAY={"id":"…"}'.

On NixOS you set the same variables in your configuration instead: Dassie on NixOS.

How much it logs

DASSIE_LOG says what reaches the journal. It is a level, trace, debug, info, warn, error or off, or directives for parts of the node, separated by commas. The unit sets info.

The node's parts are dassie::daemon, dassie::database, dassie::http, dassie::ipc, dassie::acme, dassie::auth, dassie::rpc, dassie::systemd, dassie::engine, dassie::btp, dassie::peer, dassie::routing, dassie::payment, dassie::settlement and dassie::hub; dassie alone covers all of them. dassie::front_door and dassie::market_maker belong to dassie front-door and dassie market-maker, and dassie::desktop to the desktop app. The wallet's logs page always keeps the node's last lines at info and above, and also anything more detailed you turn on here.

A relay

A relay lets clients reach your node through another node, even when yours has no public address: a front door is one. This release has no default relay built in, so a node keeps none until you name one.

A default relay is not built in yet. Once it is, a node without a domain name keeps a connection to the front door of its default name under dassiepay.net by itself. What's next

DASSIE_RELAY names a relay, by an entry of four fields: its node ID, its URL and its two public keys. A front door logs its own entry when it starts. Copy it whole:

The node keeps a relay you name whether or not it has a domain name. Set it empty, Environment=DASSIE_RELAY=, to keep no relay at all. dassie status shows the relay and whether the node is connected to it.

Why it works this way: a relay by default only for a node without a domain name.

Uplinks

A periphery node finds the core nodes it connects through, its uplinks, by itself. DASSIE_UPLINKS pins them instead: a comma-separated list of node IDs, at most 128, and the node asks only those.

A node pinned to nodes it cannot reach waits for them and asks no other. A core node ignores the list, and says so in its log when it starts. More in A server without a public IP.

Extra certificate authorities

The node checks the certificates of the servers it connects to, peers and relays among them, against the system's trusted roots. DASSIE_EXTRA_CA_FILE names a PEM file of further roots to trust beside those, for a network that uses a certificate authority of its own.

The node runs as a user of its own, in a sandbox that hides home directories, so put the file under /etc and let every user read it (chmod 644).

A proxy

On a network that blocks UDP, a periphery node reaches its uplinks over a WebSocket on their HTTPS port. If it must go through an HTTP proxy for that, it reads https_proxy or HTTPS_PROXY, and no_proxy or NO_PROXY, as other programs do. Only an http:// proxy is used; anything the node cannot use, it warns about at start and goes on without.

Other settings

  • DASSIE_PUBLIC_NAMES: more names a node without a domain name answers Open Payments to, separated by commas.
  • DASSIE_BOOTSTRAP_NODES: the bootstrap nodes, as a JSON list of entries like a relay's. This release has none built in, so a node runs alone until this names the nodes of the network it joins. The testnet's list is not built in yet: What's next.
  • DASSIE_VALIDATOR_CONFIG: the file that turns on validating settlement hubs. See Validate a settlement hub.

Dev switches warn on a public node

Three variables exist for Dassie's own development and tests, and make a node unsafe on the internet:

Variable What it does
DASSIE_PEER_ALLOW_PRIVATE=1 Peers on private and loopback addresses are reachable.
DASSIE_DEV_TIMINGS=1 The node polls, settles and reads pools every second.
DASSIE_DEV_LIVE_REALM=1 Lets a development build run the live realm. A release build refuses to start with it set.

If any of them is set while the node listens beyond loopback, it warns in its log at every start, naming the variable and what it does, and ending with It is for development; unset it on a public node. If you see that line, remove the variable from your drop-in.
